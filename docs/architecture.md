# 分层架构与职责

本项目是候选策略的 A 股规则、账户适配与 NautilusTrader（NT）执行核验层。大范围研究优先在上游列式计算与快速账户层完成，再将有限候选放入事件驱动回放。分层描述定义职责，不表示下述各层之间已有自动化服务、统一文件协议或策略转换接口。

## 研究到执行的流程

```text
数据治理与列式研究
  行情/规则/权益/日历 → 因子、信号、候选组合
         ↓
快速账户初筛（上游）
  共享资金、换手、成本与基本约束下筛选候选
         ↓
本项目：A 股适配 + NT 候选执行回放 + 独立参考核验
  原生委托/成交 → 资金/持仓/权益 → 日终差异检查与归档
         ↓
未来实盘系统（尚未验收）
  券商接入、实时风控、订单恢复、运维及账单核对
```

| 层 | 应负责的工作 | 与本项目的边界 |
| --- | --- | --- |
| 数据与列式研究 | 数据清洗、历史股票池、因子矩阵、横截面信号、参数搜索及 PIT 证据 | 输入内容指纹不能替代上游历史版本证据；缺口应明确记录或拒绝 |
| 快速账户初筛 | 以较低计算成本筛选候选，显式约定资金、成本与交易约束 | 初筛结果不替代 NT 回放；这是上游职责，本项目未新增快速引擎 |
| 本项目 | 沪深现金多头规则、共享现金、委托与成交、费用、股票权益、日终独立对账 | 以声明的 Bar 模型核验候选；不负责全量因子搜索，也不保证真实可成交性 |
| 未来实盘 | 交易通道、实时行情、风控审批、监控、恢复、券商账单核对 | NT 技术基础不等于已有可投产的券商适配或实盘验收 |

## 现有入口与数据流

当前入口是 Python `run_backtest`，不是新增的上游服务接口。调用者提供 `Instrument`、未复权 `BacktestBar`、按证券及日期索引的规则、权威 `trading_days`，以及可选公司行为与费用配置。

调用者从 `signal(bar, state)` 与 `portfolio_signal(closed_bars, state)` 中选择一个；二者返回 `OrderIntent`。上游已有信号可在调用者的回调中按决策时间读取并转换为意图，转换和可得时间检查仍由调用者负责。普通股目标权重可用 `engine.plan_rebalance`（也可从 `engine.rebalance` 导入）离线编译为数量计划，返回费用、余量及约束原因；计划不提交订单，依赖卖单完全成交的买单需依据实际账户重新计划。详见 [调仓适配](rebalance.md)。通用信号表自动导入、跨引擎自动结果对齐和实盘自动下单不属于已实现接口。

`OrderIntent` 支持可选运行内唯一 `intent_id` 和带时区 `earliest_execution`，批次全部校验成功才占用 ID 或入队；最早执行门槛以实际时刻比较且包含等号，详见 [意图契约](order-intents.md)。

策略只能在 Bar 结束后决策，意图最早于该证券下一 Bar 开始执行；组合回调在同一结束时间的输入 Bar 到齐后调用。行情是否完整、停牌如何表示及证券历史范围仍需调用者遵守数据契约。

账户回调还提供可用/预留现金、应收、NAV 和分证券估值时点；它是当时已知状态快照，日终严格对账独立执行，详见 [账户契约](account-contract.md)。

## 本项目内部

| 模块 | 当前职责 |
| --- | --- |
| `contracts`、`engine/data.py`、`engine/tushare_lake.py` | 证券与权益契约、CSV 读取、本地 Tushare 湖只读归一化与验证 |
| `engine/intents.py`、`engine/rebalance.py` | 意图批次校验与唯一 ID、最早执行时间，以及离线普通股目标权重计划 |
| `engine/backtest.py` | 运行校验、NT 事件构造、策略回调、共享账户与输出组织 |
| `engine/market_rules.py`、`engine/order_gateway.py` | 历史日规则、可卖数量、申报与资金预留检查 |
| `engine/liquidity.py` | OHLC 合成深度、共享 Bar 成交量预算及滑点压力 |
| `engine/fee_model.py`、`engine/accounting.py` | 费用与公司行为账户处理 |
| `engine/golden_ledger.py` | 独立参考资金、持仓与权益核算，供日终对账 |
| `engine/reproducibility.py` | 只读历史快照、输入及运行指纹、策略与环境记录 |

NT 原生撮合驱动订单和成交；参考账本依据成交及权益输入独立核算。日终检查原生现金、网关/原生/参考持仓以及含应收权益的 NAV，不一致即终止。这里的独立是核算路径独立；共同输入错误或共同执行假设仍可能同时通过，不能替代券商账单或市场微观结构验证。

当前实现将输入与生成事件放入内存；上游采用列式处理不意味着本项目已有流式或向量化回放。Windows/Python 3.12/NT 1.231.0 的送转桥具有固定 ABI 与指纹约束，细节见 [环境说明](environment.md)。

## 证据与验收

单元测试、供应商股票数据回放、合成转债测试、一次本地 500 股五年运行分别证明相应工程路径，不能互相替代。500 股五年运行不构成生产 SLA；实际策略的订单密度、公司行为、分钟粒度与并发量需分别测量。

执行路径采用 `bar-synthetic-l2-v1`，固定 O→H→L→C；整 Bar 成交量预算并非开盘可用流动性。详见 [执行模型](execution-model.md)、[能力矩阵](capabilities.md)、[数据契约](data-contract.md) 及 [研究使用指南](research-guide.md)。

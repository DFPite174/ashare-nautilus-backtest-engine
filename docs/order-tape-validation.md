# 第三批：冻结订单专用回放验收（2026-11-13）

版本 **2.4.0**。项目可接收上游已经确定的数量指令，以 `prepare_order_tape` → `run_order_tape` 进入执行与账户核验。本入口不运行因子或研究信号函数，原有回调入口和默认 `full` 模式保留。

## 本批交付

- `TimedOrderIntent`、`PreparedOrderTape` 与冻结工厂：限定日线收盘决策，检查全部时间、标的、数量、限价、全程 ID；保留匿名重复请求，按决策时刻稳定排序。
- 市场与指令分别留指纹。市场输入摘要不变，订单清单绑定市场摘要，换用不同市场快照会被拒绝；结果记录 `order_tape_sha256` 与 `daily-close-frozen-tape-v1` 决策契约。
- 完整市场输入仍经校验并保留摘要。每天仅为实际持仓和当时已经达到时间门槛的待执行标的投递 NT 行情，不根据未来订单或未来持仓挑选事件。
- 直接复用原有订单网关、成交、费用、资金预留、T+1、公司行为和独立日终核验。仅在收盘更新相关估值和已知历史非零量；撮合容量仍为原模型的 Bar 事后总量假设。
- 新增严格 CSV 解析与可运行样例，保留字符串 ID、显式时区和数量单位，拒绝未知列、重复列与非法行。

整进程包含导入、读取、上游输入转换、10 个场景、市场准备、指令编译和一次大样本回放；新进程不等于冷操作系统文件缓存。市场准备包含冻结、完整校验、索引和输入摘要；它不是 NT 纯撮合耗时。

市场和指令准备后，三次全新账户回放分别为 **8.11, 8.65, 8.41 秒**，中位数 **8.41 秒**；计时含事件构造、NT 执行、账户与严格核验，不含此前的输入转换、市场准备及指令编译。指令编译约 0.013 秒。此进程峰值 1866.5 MiB 包含原始输入、准备快照和多轮结果，不是单轮隔离峰值。

完整的 605069 根输入日线保持校验，NT 实际接收 **18484 根相关 Bar、41632 个市场事件**，另有 1212 个无价格日边界。相比第二批稀疏模式 1214802 个市场事件，本批减少的是审计层不需要重复处理的市场流；上游选股研究仍需处理相应全市场信息。

旧记录中第二批准备后全市场回调约 29.65 秒，本批已冻结指令执行约 8.41 秒。这是不同分工下的审计吞吐比较，不能解释为相同任意策略函数的通用框架速度排名。旧代码未在本批重新采样，也不据此宣称最快。

| 产物 | 内容及用途 |
| --- | --- |
| 每组 JSON 的 `decisions` | 收盘决策时间、最早执行时间、当时实际现金/持仓/可卖量、信号权重、规划数量和规划约束；每个请求保存明确 `intent_id` |
| `execution_outcomes` | 按意图关联请求/成交/剩余数量、费用、拒单原因、期末未执行原因、原生订单状态；区分 `FILLED`、`PARTIALLY_FILLED`、`REJECTED`、`PENDING`、`UNFILLED` |
| `result` | 原有完整订单、成交、拒单、每日账户、权益和运行 manifest；不因增加摘要而删掉原始业务证据 |
| `summary.json` | 每组结果文件 SHA-256、输入/代码/策略/费用/模型指纹、结果计数、分段耗时和完整重复比较结果 |

未知意图或超额成交使关联报告失败；不把无法解释的未成交一律归咎于流动性。不增加人工推测的原因。规划阶段的 `CASH_SHORTAGE` / `INACTIVE` 等保留在 `allocations.reasons`；真实执行拒单另见 `rejection_reasons`，不混为同一阶段。未完成目标按既定政策在下次调仓依据真实账户重算，不自动补单。

`weight_deviation` 仍是决策时实际权重与当前目标的差额，**不是成交后达成率**。执行缺口看按意图的未成交数量；最终暴露看每日账户。结果解释不承诺可以从净值差额唯一推导某一约束的收益影响。

完整比较由公共 `compare_complete_backtests` 承担，旧比较接口不变，详见[结果比较契约](result-comparison.md)。新增验证覆盖额外订单/未执行/权益的首差、缺失字段失败、随机原生 ID、模型差异门槛，以及部分成交、资金拒单和数据结束未执行的关联解释。

| 本机实测，三次新进程 | 结果 |

| 5 次回放累计，三次 | 1.394 / 1.347 / 1.457 秒；包含执行与引擎核验 |

测量复用既有可选 `psutil` / Windows `peak_wset` 探针，读取操作系统记录的进程峰值，覆盖加载与准备阶段，包含原生分配；缺失时报告 `MEASUREMENT_INCOMPLETE`，不填零。它不是 Python `tracemalloc`。没有清空操作系统文件缓存，所以属于**新进程测量，不是磁盘冷缓存测量**；峰值也包含测量探针开销。

该代表用例低于 60 秒排查预算，没有 OOM/等待阻断。结论是暂不继续优化执行内核；本次未做与其他引擎的速度排名。上述小池数据不能替代 500 股五年或更多真实候选的吞吐验收，原 20 秒/1 GiB 目标状态不变。

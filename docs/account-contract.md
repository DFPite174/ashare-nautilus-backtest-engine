# 账户快照契约

策略回调接收 `ResearchState`。原有 `cash`、`positions`、`sellable`、`history` 保留；新增字段采用默认值以保持原有构造兼容。运行时引擎填入以下当时已知状态，映射通过增量版本提供只读视图，历史使用固定长度快照，保存后不会暴露未来回放新增或更新的状态。

| 字段 | 语义 |
| --- | --- |
| `as_of` | 回调对应的 Bar 结束时间；组合回调为共同结束时间 |
| `cash` | 参考账本现金，包含已经到账的现金，不包含未到账红利 |
| `reserved_cash` | 活动买单预留金额合计，含预计费用 |
| `available_cash` | `cash - reserved_cash`，预留不是现金流 |
| `positions` / `sellable` | 总持仓 / 网关按当前交易日与锁定计算的可卖量 |
| `receivables` | 参考账本尚未到账的应收红利合计 |
| `valuation_prices` | 各证券当前已知估值参考价 |
| `valuation_times` | 各估值参考价更新时刻，不保证各证券相同 |
| `nav` | `cash + receivables + Σ(positions[s] × valuation_prices[s])`，只累加非零持仓 |
| `history` | 回调时点已结束并处理的各证券 Bar 历史 |

`as_of` 不表示每个估值价都在该时刻更新。正常收盘更新该证券收盘价；较新的成交可更新其参考价；除权日按现金红利和送转比例调整已知参考价。停牌或异步行情下不同证券可能使用更早参考价，应检查 `valuation_times`。除权参考价也不是新的观测成交价。`nav` 是已知价格下的账面权益，不保证持仓能按该价格变现。

## 历史与快照的内存边界

增量映射捕获当前版本，旧视图仍读取捕获时的值；后续更新不会改变它们。引擎通过弱引用跟踪存活视图，并在对应键再次更新时回收不再需要的旧版本。若策略长期保存旧 `ResearchState` 或其映射视图，为维护旧视图而保留的版本会增加内存；弱引用不会强行回收调用方仍在使用的视图。只需摘要时，可保存所需标量并释放旧状态引用。

原生引擎的 Bar 和 Tick 缓存容量各为 2，不是策略历史长度上限。策略自有 `state.history` 仍保留全部已处理输入 Bar，每个历史快照只暴露捕获时的前缀。缓存缩减不使完整研究历史变为常量内存。`full`、`session` 和 `sparse` 三种投递模式均将原始输入 Bar 用于信号、历史和估值；详见 [行情投递模式](data-delivery.md) 与 [准备数据复用](prepared-data.md)。

## 日内处理顺序

交易日开始时先滚动网关及参考账本可卖批次、更新费用日期并处理已符合条件的非开放证券待执行意图，再处理除权/送转、应收及应付红利到账。公司行为日期落在回放区间内时也安排相应日期事件。

Bar 内按声明的合成路径执行成交并更新持仓、现金、费用及买单预留；成交会扣减预留，取消、到期或拒绝释放相应预留。Bar 结束后更新已知价格与历史，再产生回调快照；组合回调等同一结束时间的输入 Bar 收齐。快照供决策使用，回调返回的意图随后才整批校验并排入未来符合时间条件的 Bar。

日终撤销活动订单、处理未纳入历史的非活动 Bar 和符合条件的非开放待执行意图，按已知价格计算参考权益并记录登记日权益，再执行严格对账。日终事件和 Bar 回调在同一标称时间附近由引擎事件顺序驱动；不要把每次策略回调视为已完成日终对账的验收快照。

## 严格核验边界

日终要求原生现金等于参考现金，原生持仓、网关持仓与参考持仓逐证券精确一致；原生现金加持仓估值及独立应收，与参考权益的差异不得超过 `0.000001` 元，否则终止运行。成交时另核对原生与独立估计费用。每个交易日必须产生日终记录。

新增快照字段暴露决策时已知状态，不放宽原有日终断言，也不构成每个事件后的实时三方对账。参考核算仍使用同一批行情和权益输入；共同输入错误、估值陈旧、合成撮合偏差不会因账目一致而自动消失。详见 [执行模型](execution-model.md) 与 [能力矩阵](capabilities.md)。

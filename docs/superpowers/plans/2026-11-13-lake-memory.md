# P1：本地湖输入内存

沿用用户已批准的必要输入准备优化。保留 `LakeInputs`、源文件指纹、所有市场事实及异常检查，不新增公共接口。

基线：实际本地 Tushare 湖的固定 500 股/2021–2025 输入为 605069 Bar、606000 规则、1943 权益事件；直接适配输入摘要 `99058bfb343ea9854dd88f09d22abb3311362cfee92bb343343a7d0a736a2c05`。该路径使用适配器默认权益策略，不与冻结实验的另一份输入摘要混同。

1. 先记录旧适配器新进程加载和准备峰值，再写分批投影读取、跨批重复与缺口回归。
2. 市场表投影到现有实际使用列，8192 行分批读取为具名元组，索引检查仍跨批/跨年；较小元数据及权益保留原实现。
3. 同一会话时间复用；转换后移除临时行情/价格带索引项，避免大表临时 Python 字典与最终输入长期共存。
4. 完整测试与独立 wheel，实际湖前后各三次；比较全部源指纹、快照、输入数量及摘要。冻结财务场景另行回归，不把直接湖适配等同策略收益实验。
5. 原 500 股冻结订单性能实验入口不改，不把新输入路径和原实验耗时混用。原始数据只读且不上传。

完成记录：源码和独立安装包完整测试各 339 项；实际生产湖前后三次加载/准备保持输入摘要、全部源文件指纹及快照一致。加载含导入中位数 14.21→7.93 秒，全程峰值 2429.6→1317.8 MiB；冻结 10 场景及 500 股财务轨迹另一次回归通过。1 GiB 和完整执行 ≤20 秒尚未在本路径验收，见[第六批验收](../../lake-memory-validation.md)。

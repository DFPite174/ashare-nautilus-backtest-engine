# 第四批：数据准备与内存优化（2026-11-13）

版本 2.5.0。本批保留完整数据校验、同一输入指纹、订单模型和三方账户核验，优化准备阶段的重复工作。

## 修改

- 冻结规则按字段结构共享只读索引，每行保存不可变值元组，减少重复字典。未知嵌套元数据仍递归冻结，字段类型、缺失值、Decimal 精度和额外字段保留；只有纯字符串字段名共享结构。
- 同一交易日的开收盘和午休边界复用，减少逐行创建日期时间对象。
- 哈希复用数据类字段定义、受限缓存标准时区的 UTC 编码，并取消浅层映射二次排序；相同字符串键的覆盖顺序、夏令时 fold 与旧摘要保持兼容。
- 原始输入仍与准备快照共存；本批没有引入列式输入或磁盘缓存。

## 验证

源码及独立 wheel 安装完整测试各 **327 passed**。同一 500 只股票、2021—2025 年、605069 根日线、1212 个交易日、1170 个冻结指令，三次新进程及三次准备后回放均与旧业务基线匹配。比较成交、费用、拒单、逐日现金/持仓/权益、最终账户与完整公司行为事件内容；10 个工程场景也全部匹配。大样本 1155 笔成交。

准备后的三次回放为 8.29, 8.55, 8.46 秒，中位数 8.46 秒。实际投递仍为 41632 个市场事件及 18484 根原生 Bar，全部输入日线仍参与校验与摘要。

整进程包括导入、读盘、上游输入转换、10 个场景、市场准备、指令编译和一次大样本回放；新进程不等于冷操作系统缓存。准备后计时包括事件生成、执行和账户核验，不包括前面的数据准备。未开启 profiler 或 tracemalloc。

单次阶段诊断中，规则冻结约 3.90→2.53 秒，准备完成进程峰值约 1456→1331 MiB，哈希仍约 10 秒。诊断不是正式重复测试；原始输入转换结束时峰值已约 1272 MiB，表明仅压缩准备快照无法实现整进程 1 GiB。

## 门槛与后续

首次运行 ≤20 秒和峰值 ≤1 GiB 仍未达标。准备后 ≤10 秒只针对本冻结指令样本，不是全市场任意策略的速度保证。下一步先处理上游 Python 行对象和列式输入转换，再优化摘要编码；完整数据覆盖、摘要兼容及账户轨迹必须继续作为硬门槛。高持仓宽度与高订单密度压力仍需单独测试。

这里验证的是执行模型内一致性。日线 O-H-L-C 合成路径、Bar 事后总量容量假设、历史数据缺少严格 vintage PIT、送转内部 ABI 依赖均保持原边界；不构成真实 L2、实盘或策略收益证明。

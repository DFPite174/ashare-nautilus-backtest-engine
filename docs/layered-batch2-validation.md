# 分层执行验证：第二批验收（2026-11-13）

版本 2.3.0。此批交付同进程准备数据复用、时点隔离增量快照、流式/日线稀疏原型和原生业务比较工具。默认仍为 `data_mode="full"`；本报告性能对应显式 `sparse`，不代表默认调用自动变快。

## 已完成

- `prepare_backtest` 固定输入、校验日历/规则/行情/权益并缓存输入指纹；`run_prepared_backtest` 每轮建立新账户、订单、费用累积及独立账本，逐轮检查运行参数。
- 源容器变更与准备快照隔离；嵌套映射只读；自定义可变时区被拒绝。校验器改变需重新准备。同进程复用，不加载磁盘或 pickle 缓存。
- 账户、可卖、历史、价格及估值时点用版本视图捕获；旧视图不见未来键和值，弱引用回收不再使用的视图。保留旧视图会保留历史版本。
- 持仓市值增量更新；日终与参考市值及可卖/持仓缓存交叉核验。部分卖单日终预留释放的同步漏点已由回归识别并修复。
- 内置普通股/可转债费率按资产组计算日期策略；自定义子类与实例替换方法仍逐证券处理。
- `session` 使用 NT 公开流式接口逐日装载；`sparse` 仅日线，为当日开盘前已知且合资格的待执行意图保留六事件路径，其余证券保留 CLEAR+Bar。保留全部行情供信号、历史与估值使用。
- NT L2 要求存在簿数据，因此 idle CLEAR 仍需保留；没有绕过输入检查。无价格的自定义日边界推进收盘定时器，然后释放本批原生事件与流动性元数据。
- 原生 Bar/tick 缓存只保留最近两条；回调的自有研究历史完整保留。减少重复订阅和行情查找索引开销。
- `compare_backtests` 校验相同输入和经济假设，定位成交、拒单、每日账户首差与最终资金持仓差异；显式允许不同模型时报告假设差异。

## 结论与后续门槛

在同一冻结经济契约下，本批减少无订单证券的原生事件与全量事件常驻内存，并使市场校验/指纹可跨候选复用。**新进程 ≤20 秒、准备后回放 ≤10 秒、峰值 ≤1 GiB 的目标仍未达到，不能据此称为最快或第一梯队。**

下一步先分离准备/原生事件/回调/核验的剩余成本，验证按日截面批量投递或复用适合低频的快速账户后端；NT 路径继续承担声明模型下的执行核验。专门活动订单索引、派生统计开销、上游快速层差异归因和落选抽检、更高持仓/订单密度压力仍在 [执行计划](superpowers/plans/2026-11-12-layered-validation.md) 中。改变执行模型必须重新建立共同契约，不通过删掉资金/费用/权益约束换取速度。

实验运行器保留历史版本标签；实际代码以源码指纹和本批 Git 提交为准，2.3.0 安装包另行构建验收。当前供应商历史快照没有严格 vintage PIT 证明，日线合成盘口不能证明真实队列成交；可转债仍只有基础合成交易证据，尚未新增真实转债生命周期或实盘接入。
